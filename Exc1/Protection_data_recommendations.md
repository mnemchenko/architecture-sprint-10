# Список инструментов, способов и мер по защите данных

- Шифровать данные на диске с управлением ключами через KMS
- Внедрить централизованное хранилище данных с шифрованием (в базе данных) с управлением ключами через KMS
- Разграничить доступ к данным по RBAC и согласно принципу минимальных привилегий. Например:
  - Врачи: Доступ к медицинским картам только своих пациентов
  - Ресепшен: Доступ к записям пациентов, но без доступа к диагнозам
  - Кассиры: Только к платежной информации
  - Бухгалтерия: Только финансовые операции
- Проводить аудиты учетных записей и удалять записи сотрудников, которые уволились
- Ввести двухфакторную аутентификацию (2FA)
- Шифровать данные при передаче в централизованную систему при помощи TLS 1.2
- Осуществлять регулярное резервное копирование данных с шифрованием. Доступ к копиям должен быть только у администратора
- Регулярно осуществлять тестирование восстановления данных
- Ввести логирование и аудит доступа к данным
- Брать согласие с клиента в явном виде при заключение договора на передачу персональных данных
- Брать согласие на передачу медицинских данных
- Настроить ETL для анализа с обфускацией данных (тк оригинальные данные PII не нужны при построении отчетов)
- Разработать политику конфиденциальности и брать согласие с ней с клиентов
- Предусмотреть процедуру анонимизации персональных данных при просьбе от клиента об удалении
- Провести обучение сотрудников по работе с персональными и медицинскими данными
- Перестать обмениваться файлами через e-mail. Возможно, в будещем внедрить систему контроля утечек (DLP)
- Использовать объектное хранилище для файлов (например, файлов анализова) с шифрованием и доступом согласно RBAC
- Ограничить доступ к системам только с IP клиник через VPN, разделить служебный и публичный Wi-Fi клиники

## Тегирование

### Политика тегирования
Все данные из категории PII помечаем тегом PII, из категории PHI – тегом PHI, финансовые данные – тегом finance.
Такой подход позволит настроить дополнительные проверки при внедрении RBAC, основанные на тегах. Также он позволит легко обезличивать данные при выгрузке для анализа.

Также тегируем по источникам данных: лаборатория – lab, бухгалтерия – bookkeping, врач – doctor, ресепшен – reception.

Поможет при анализе данных определить, из какого источника данные были получены.

### Инструмент тегирования

Для тегирования данных в централизованном хранилище будем использовать BigID

Преимущества:
- Автоматическое обнаружение и классификация данных из различных источников, включая базы данных, файловые хранилища и облачные сервисы.
- Глубокая интеграция с PII и PHI данными, что критично для медицинской сферы.
- Поддержка Data Lineage, позволяющая отслеживать перемещение и изменения данных.
- Гибкая система тегирования, совместимая с политиками RBAC и ABAC.
- Возможность интеграции с SIEM и DLP решениями для предотвращения утечек данных.

Альтернативные решения:

Collibra – хороша для визуализации потоков данных, но менее гибкая в автоматическом классификаторе.

OneTrust – сильна в управлении согласиями пользователей, но требует сложной настройки.

Apache Atlas – подходит для экосистемы Hadoop, но не так удобен для медицинской отрасли.
